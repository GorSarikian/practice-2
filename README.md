# Практическая работа №2, вариант 17

Дисциплина «Конфигурационное управление», ИКБО-14-25.
Язык реализации: Java 17+, только стандартная библиотека JDK.

## Этап 1

Минимальное CLI-приложение читает TOML и печатает параметры в формате ключ=значение.
Все семь обязательных параметров проверяются; ошибки выводятся в stderr, код завершения 1.

```powershell
$env:JAVA_HOME = 'C:\path\to\jdk-17'
.\build.ps1
.\run.bat stage1 examples/test.toml
.\build.ps1 -Test
```

На Linux/macOS: `sh run.sh stage1 examples/test.toml`, тесты: `sh run.sh test`.
Нужен JDK, одного JRE недостаточно. Maven/Gradle и сторонние Java-библиотеки не нужны.

## Конфигурация

Все пути считаются от каталога TOML. Поддерживаются плоские TOML-пары: bare keys,
строки в одинарных/двойных кавычках, escape-последовательности TOML, bool,
десятичные целые, комментарии. Таблицы, массивы и многострочные строки не нужны схеме и отклоняются.

| Ключ | Тип | Назначение |
|---|---|---|
| package | string | Имя NuGet-пакета; в тестовом режиме только A-Z |
| repository | string | URL NuGet V3 service index или путь к тестовому файлу |
| test_mode | bool | true: локальный тестовый репозиторий |
| output | string | Путь PNG, родительские каталоги создаются при экспорте |
| ascii_tree | bool | Включить ASCII-дерево |
| max_depth | integer | 0..128; корень имеет глубину 0 |
| filter | string | Исключаемая подстрока; пустая строка отключает фильтр |

Дубликаты, неизвестные ключи, неверные типы и отсутствующие обязательные значения запрещены.
См. `examples/test.toml`; проверки конфигурации находятся в `tests/nugetgraph/ConfigTests.java`.
