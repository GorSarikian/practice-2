# Практическая работа №2, вариант 17

Дисциплина «Конфигурационное управление», ИКБО-14-25.
Язык реализации: Java 17+, только стандартная библиотека JDK.

Инструмент самостоятельно получает зависимости NuGet-пакетов, строит граф рекурсивным
DFS, исключает пакеты по подстроке, ищет обратные зависимости, выводит ASCII-дерево
и сохраняет описание D2 и изображение PNG. Реализованы все пять этапов варианта 17.

## Быстрый запуск

Нужны JDK 17+ и [D2 0.9.0+](https://d2lang.com/tour/install/).
Java используется для всей логики приложения; D2 используется только для отрисовки.

```powershell
$env:JAVA_HOME = 'C:\path\to\jdk-17'
$env:D2_COMMAND = 'C:\Tools\d2\d2.exe'
.\build.ps1 -Test
.\run.bat examples/test.toml
.\run.bat examples/logging.toml
```

Если javac/java и d2 уже в PATH, переменные не нужны. D2_COMMAND содержит путь к
исполняемому файлу, без дополнительных аргументов. Все сетевые примеры используют
NuGet.org и фиксированные версии для воспроизводимости.
Результаты: `generated/*.d2`, `generated/*.png`; этот каталог исключён из Git.

| Команда | Результат |
|---|---|
| run.bat stage1 config.toml | Валидация и вывод параметров |
| run.bat stage2 config.toml | Только прямые зависимости |
| run.bat stage3 config.toml | Граф в виде списков смежности |
| run.bat stage4 config.toml | Прямые и транзитивные обратные зависимости |
| run.bat stage5 config.toml | D2, PNG и, при включении, ASCII-дерево |
| run.bat config.toml | Сокращение для stage5 |

Режимы демонстрации этапов 1, 2 и 4 сохранены отдельными командами;
при обычном запуске их служебный вывод не добавляется.

## Этап 1

Минимальное CLI-приложение читает TOML и печатает параметры в формате ключ=значение.
Все семь обязательных параметров проверяются; ошибки выводятся в stderr, код завершения 1.
`powershell -File demo-errors.ps1` демонстрирует отдельную ошибку для каждого параметра.

```powershell
$env:JAVA_HOME = 'C:\path\to\jdk-17'
.\build.ps1
.\run.bat stage1 examples/test.toml
.\build.ps1 -Test
```

На Linux/macOS: `sh run.sh stage1 examples/test.toml`, тесты: `sh run.sh test`.
Нужен JDK, одного JRE недостаточно. Maven/Gradle и сторонние Java-библиотеки не нужны.

## Конфигурация

Все пути считаются от каталога TOML. Поддерживаются плоские TOML-пары: bare keys,
строки в одинарных/двойных кавычках, escape-последовательности TOML, bool,
десятичные целые, комментарии. Таблицы, массивы и многострочные строки не нужны схеме и отклоняются.

| Ключ | Тип | Назначение |
|---|---|---|
| package | string | Имя NuGet-пакета; в тестовом режиме только A-Z |
| repository | string | URL NuGet V3 service index или путь к тестовому файлу |
| test_mode | bool | true: локальный тестовый репозиторий |
| output | string | Путь PNG, родительские каталоги создаются при экспорте |
| ascii_tree | bool | Включить ASCII-дерево |
| max_depth | integer | 0..128; корень имеет глубину 0 |
| filter | string | Исключаемая подстрока; пустая строка отключает фильтр |

Дубликаты, неизвестные ключи, неверные типы и отсутствующие обязательные значения запрещены.
См. `examples/test.toml`; проверки конфигурации находятся в `tests/nugetgraph/ConfigTests.java`.

## Этап 2: NuGet

`run.bat stage2 examples/logging.toml` печатает прямые зависимости выбранной версии.
Приложение само читает NuGet V3 service index, находит PackageBaseAddress/3.0.0,
получает список версий и XML `.nuspec` через `java.net.http`. JSON, диапазоны версий
и выбор группы зависимостей реализованы самостоятельно; XML разбирается JDK DOM с запретом DTD.
NuGet/dotnet и сторонние библиотеки для извлечения зависимостей не вызываются.

Дополнительные TOML-параметры:

| Ключ | По умолчанию | Назначение |
|---|---|---|
| package_version | "latest" | Точная версия корня; latest выбирает наибольшую стабильную |
| framework | "net8.0" | net5.0+ либо netstandard2.0/2.1 |
| reverse_package | имя корня | Цель поиска обратных зависимостей на этапе 4 |

Для каждой зависимости выбирается минимальная доступная версия, удовлетворяющая диапазону.
Поддерживаются bare minimum, [exact], открытые/закрытые и неограниченные интервалы.
Prerelease допускается, когда он явно указан в диапазоне; latest выбирает stable.
Floating ranges в nuspec запрещены форматом NuGet и отклоняются.
Идентификаторы NuGet нечувствительны к регистру, в графе приводятся к lowercase.

Для modern .NET выбирается ближайшая совместимая группа net, затем netcoreapp<=3.1,
затем netstandard<=2.1, затем группа без платформы. Для netstandard выбирается
совместимая группа netstandard. Пустая выбранная группа означает отсутствие зависимостей.
Старый .NET Framework и платформенные TFM не поддерживаются; отсутствие совместимой
группы даёт явную ошибку. Полный NuGet restore с глобальным разрешением конфликтов не реализуется.

Сетевые ошибки, HTTP-статусы, некорректные метаданные и отсутствующие версии дают код 1.
Метаданные кешируются на время запуска. Сетевые тайм-ауты: соединение 15 с, запрос 30 с.

Официальные спецификации:
[NuGet API](https://learn.microsoft.com/en-us/nuget/api/package-base-address-resource),
[nuspec](https://learn.microsoft.com/en-us/nuget/reference/nuspec),
[диапазоны версий](https://learn.microsoft.com/en-us/nuget/concepts/package-versioning),
[разрешение зависимостей](https://learn.microsoft.com/en-us/nuget/concepts/dependency-resolution).

## Этап 3: рекурсивный DFS

```text
run.bat stage3 examples/test.toml
run.bat stage3 examples/diamond.toml
run.bat stage3 examples/filtered.toml
run.bat stage3 examples/logging.toml
```

Тестовый формат: `A: B C`, затем `B:`, `C:` и другие объявления, по одному на строку.
Имена состоят из A-Z, `#` начинает комментарий. Все упомянутые вершины должны быть объявлены.
Допускаются циклы, петли и несвязные компоненты; повторные рёбра убираются.

Корень имеет глубину 0. max_depth=0 оставляет только корень без запросов его зависимостей.
Ребро добавляется, если глубина дочернего узла не превышает лимит.
Граница помечается `[depth limit]`: зависимости такого узла ещё не исследованы,
поэтому отсутствие рёбер не обязательно означает настоящий лист.

DFS реализован рекурсией в `GraphBuilder.visit`. Множество активного пути останавливает
цикл, сохраняя замыкающее ребро. Таблица оставшегося бюджета глубины позволяет повторно
раскрыть общий узел, если другой путь к нему оказался короче. Это сохраняет все вершины,
достижимые в пределах лимита; глубина ограничена 128 для безопасности стека.

Фильтр сравнивается с именем без учёта регистра и исключает узел вместе с его веткой.
Пустой фильтр ничего не исключает. Если фильтр совпал с корнем, граф пуст.
Исключённые NuGet-зависимости пропускаются до запроса списка их версий.
Граф отражает метаданные package@version, а не итог установки: в разных ветках могут
присутствовать разные версии одного пакета.

## Этап 4: обратные зависимости

`run.bat stage4 examples/reverse.toml` ищет зависящие от E пакеты.
Рёбра разворачиваются, после чего используется тот же рекурсивный `GraphBuilder`.
Вывод включает прямых и транзитивных потребителей; исходная цель присутствует как корень,
но не считается собственным потребителем. Циклические рёбра сохраняются.
max_depth ограничивает расстояние от цели в обратном графе.

Локальный тестовый файл задаёт весь конечный репозиторий: поэтому поиск включает
потребителей из несвязных с исходным package компонент, например F -> E.
Для удалённого NuGet область поиска ограничена графом, достижимым от package
в пределах max_depth и filter: NuGet V3 не предоставляет прямого API полного
поиска обратных зависимостей всех пакетов. Если цель отсутствует в этой области,
приложение выдаёт ошибку, а не заявляет об отсутствии потребителей во всём NuGet.
Все найденные версии reverse_package в области анализа учитываются.

Примеры: E имеет прямых потребителей C и F; G не имеет потребителей;
при глубине 1 для E остаются E, C, F. Эти случаи проверяются автоматически.

## Этап 5: D2, PNG и ASCII

В D2 каждая вершина получает отдельный безопасный идентификатор n0, n1 и т. д.;
полное имя и версия выводятся в подписи. Направление ребра: пакет -> его зависимость.
Корень выделен цветом, граница глубины помечена `[depth limit]`.
Никаких PNG из сторонних источников приложение не скачивает: оно запускает D2
с собственным текстовым описанием. Отрисовка имеет тайм-аут 90 с, проверяются код
завершения, PNG-сигнатура и читаемость изображения. При ошибке старый PNG сохраняется,
а новый `.d2` остаётся доступен для диагностики. Наличие файла само по себе не считается успехом.

ASCII-дерево использует только `|--`, `\--`, пробелы и текстовые подписи.
`[cycle]` означает возврат к предку, `[shared]` - уже показанный узел,
`[depth limit]` - нераскрытую границу. Повторный более короткий путь раскрывается заново.

```text
run.bat examples/newtonsoft.toml
run.bat examples/logging.toml
run.bat examples/serilog.toml
run.bat examples/diamond.toml
run.bat examples/filtered.toml
```

Для Linux/macOS используются те же параметры с `sh run.sh`.
Официальная документация [экспорта D2](https://d2lang.com/tour/exports/).

## Проверка и сравнение

`build.ps1 -Test` / `sh run.sh test` запускает офлайн-тесты, не требующие сети, D2 и .NET.
Проверяются TOML, все настройки, JSON, версии и интервалы, группы nuspec, ошибки API,
циклы, петли, глубина, фильтры, общий узел, обратные зависимости, D2, ASCII и сбои рендера.
`SourceRules` через AST компилятора JDK проверяет Java-код: <=1000 строк в файле,
<=120 символов в строке, <=40 строк в методе, <=7 аргументов, сложность <=10
(учитываются ветвления, циклы, catch, case, тернарные операторы и &&/||).

Для независимого сравнения нужен .NET SDK 8.0.4xx+ с `dotnet nuget why`:

```powershell
.\compare-native.ps1
# либо:
.\compare-native.ps1 -Dotnet 'C:\Tools\dotnet\dotnet.exe'
```

Скрипт выполняет штатный restore отдельных тестовых .NET-проектов,
печатает `dotnet list package --include-transitive` и дерево `dotnet nuget why`,
после чего автоматически сравнивает все вершины, версии и рёбра с Java-графом.
Эти вызовы служат только проверкой: Java-приложение не использует dotnet/NuGet CLI.
NuGetAudit=false отключает нерелевантный проверке аудит у трёх изолированных примеров.
Пользовательские настройки источников не меняются.

Фактические результаты и объяснение возможных расхождений: [docs/verification.md](docs/verification.md).
Штатный инструмент: [dotnet nuget why](https://learn.microsoft.com/en-us/dotnet/core/tools/dotnet-nuget-why).

## История этапов и публикация

В Git сохранены пять последовательных scoped Conventional Commits: config, nuget,
graph, reverse, visualization. Каждый коммит добавляет работающий этап и его проверки.

В Git не включаются скомпилированные классы, изображения, архивы, obj/bin и настройки IDE.
Готовые PNG можно получить командами из этого README; текстовая проверка сохранена в docs.
После создания **пустого публичного** репозитория в своём аккаунте, без README/лицензии:

```text
git remote add origin https://github.com/GorSarikian/practice-2.git
git push -u origin main
```

Эти команды требуют GitHub-аутентификации. Ссылка является предполагаемым адресом
для публикации, а не утверждением о существовании репозитория.
