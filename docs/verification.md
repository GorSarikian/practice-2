## Как интерпретировать сравнение

В выбранных трёх случаях состав графа совпал полностью. Newtonsoft.Json при net8.0
выбирает пустую совместимую группу net6.0 и действительно не имеет пакетных зависимостей.
Logging даёт общие узлы; Serilog.Extensions.Logging добавляет две вершины и два ребра
к графу Logging. Версия транзитивного Serilog - 3.1.1.

`dotnet nuget why` рисует только пути к запрошенному пакету, поэтому его дерево
содержит меньше веток, чем полный граф приложения. Например, при поиске причин
наличия DependencyInjection.Abstractions ветка Options -> Primitives не показывается.
Это различие формы представления, а не потерянная зависимость; полная проверка
рёбер выполнена по assets-файлу. ASCII приложения помечает повторные узлы `[shared]`,
тогда как штатный инструмент может повторять их на каждом пути.

Для произвольных пакетов возможны содержательные расхождения: NuGet restore
глобально разрешает конфликты версий, применяет direct-dependency-wins и другие
правила. Здесь каждая ветвь независимо выбирает минимальную версию, подходящую
диапазону, и может сохранить несколько версий одного пакета. Платформенные TFM,
старый .NET Framework, runtime assets и framework references не моделируются.
Фильтр и ограничение глубины намеренно сокращают анализ. `latest` использует
стабильные версии из flat-container, который может включать unlisted-версии.

## Тестовые демонстрации

- graph.txt: A -> B -> D -> A и A -> C -> D, C -> E; обход завершается, цикл сохранён.
- diamond.toml: глубина 2, вершины A/B/C/D; зависимости D не запрашиваются и отмечены границей.
- filtered.toml: исключён D, остаются A/B/C/E; цикл исчезает вместе с исключённым узлом.
- reverse.toml: прямые потребители E - C и F, транзитивные - A, D, B; цикл не зацикливает поиск.
- G не имеет обратных зависимостей; при обратной глубине 1 для E остаются E/C/F.
- Отдельный тест длинного и короткого пути подтверждает повторное раскрытие общего узла.

В удалённом режиме обратный поиск ограничен анализируемым графом корня.
Полный обратный поиск по всему NuGet.org не заявляется; для конечного тестового
репозитория исследуются все компоненты.
